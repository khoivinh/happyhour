# 2026-06-02 — Relative-time half-hour offset fix + auth investigation

## What changed

### Fixed: India Standard Time relative offset truncated to whole hours
Cities in sub-hour zones (India UTC+5:30, etc.) showed a whole-hour relative
offset in Relative Time mode (e.g. `+10HR` instead of the correct `.5`). Root
cause: the relative offset was wrapped in `Math.round()` at the display layer,
collapsing the half-hour even though `offset` is stored as a fractional number
(`getGmtOffset` returns `hours + minutes/60`).

| File | Change |
|------|--------|
| `client/src/components/time-zone-converter.tsx:176` | Removed `Math.round()` from the sortable tile's `relativeOffset` |
| `client/src/components/time-zone-converter.tsx:726` | Removed `Math.round()` from the drag-overlay tile's `relativeOffset` |
| `client/src/components/digital-clock.tsx:173` | `formatRelativeOffset` now renders the fractional part (rounds to 2 decimals to kill float noise; trailing zeros dropped by `Number`→string) |

`tsc --noEmit` clean.

Note on the spec value: the edit doc asked for `+10.5HR`, which is the
standard-time (winter) value (NY at UTC−5). It's currently DST (June, NY at
UTC−4), so the correct live value is `+9.5HR`. The fix preserves whichever is
right for the season — the half-hour is no longer lost.

### Investigated (no code change): auth aggressiveness
The edit doc flagged (1) being logged out after a few days and (2) an email
code on same-device re-login. Both are **Clerk Dashboard** settings, not code:
- `App.tsx` passes no session options to `<ClerkProvider>`; sign-in is Clerk's
  hosted `<SignInButton mode="modal">`. No session-timeout, MFA, or OTP code
  exists in the repo.
- Logout frequency → Clerk **Sessions** (inactivity timeout / session lifetime).
- "2FA email code" is most likely the **primary** email-OTP sign-in method
  (no password configured), not a second factor. Fix by extending session
  lifetime and/or adding a password or Google/Apple social login.

## Decisions
- Kept the rounding-to-2-decimals guard in `formatRelativeOffset` rather than
  raw interpolation, so any float drift can't surface as `+9.500000001HR`.

### Resolved: auth friction (Clerk Dashboard, Production instance)
- **Email code on re-login** — turned OFF "Sign-in with email → Email
  verification code" (account already has a password, so no lockout risk).
  Re-login is now email + password, no code. Sign-up email verification left on.
- **Logged out after a few days** — production session lifetime is capped at
  Clerk's 7-day default on the free (Hobby) plan; extending it needs a paid
  plan. Accepted the 7-day cadence since the password fix makes the weekly
  re-login painless. Revisit (Clerk Pro) only if it still annoys.
