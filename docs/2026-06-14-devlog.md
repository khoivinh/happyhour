# 2026-06-14 — Safari time-edit slashed-zero fix

## What changed

### Fixed: slashed zeros in the time-edit input on Safari (macOS)
Clicking a clock to edit its time opens a native `<input type="time">`. On
Safari/macOS the digits rendered with slashed zeros while the read-only clock
display showed plain zeros; Chrome/Firefox showed plain zeros in both.

Root cause: the input and the display share the same `font-display` class
(Zalando Sans), so it's the same font — but Safari's UA stylesheet renders
`input[type=time]` with **tabular figures**, and Zalando Sans's tabular `0` is
the slashed variant. The live-clock `<p>` uses the default proportional
figures (plain oval `0`). Not a font-loading/fallback issue.

| File | Change |
|------|--------|
| `client/src/components/digital-clock.tsx:502` | Desktop time input: added `[font-variant-numeric:proportional-nums] [font-feature-settings:'zero'_0]` |
| `client/src/components/digital-clock.tsx:557` | Mobile time input: same |

Two utilities cover both possible sources of the slash: `proportional-nums`
overrides Safari's tabular default, and `'zero' 0` disables the OpenType
slashed-zero feature as belt-and-suspenders. `tsc --noEmit` clean.

## Decisions
- Chose `proportional-nums` (matches the live clock exactly) over
  `tabular-nums`, even though tabular figures keep digit columns from
  shifting — visual parity with the display mattered more for a single time
  field.
