# 2026-07-15 — Onboarding tagline above "Add Time Zone"

Spec: `Scratch/2026-07-15-happyhour-edits.md`. Figma: `329:3241` (frame), `338:3813` (tagline node).
All changes in `client/src/components/time-zone-converter.tsx`. Shipped to `main`.

## Why

New visitors don't immediately grasp what Happyhour is. Added a one-time onboarding headline —
"Welcome to the indispensable world clock." — above the "Add Time Zone" button. On the user's
first-ever add it fades and the button + tile grid animate up into place, then never returns.

## The empty-state problem

The spec's trigger ("after the user adds her first custom clock tile") assumes an empty start, but
the app is **never empty**: it seeds 3 default tiles (`DEFAULT_ZONES`) and `handleRemoveClock` refuses
to drop below 1. Khoi's call: gate on a persistent "has ever added a zone" flag and keep the seeded
tiles (this matches the Figma frame, which shows the tagline sitting above populated tiles).

## What changed

| Concern | Implementation |
|---|---|
| Flag | `ONBOARDED_KEY = "world-happyhour-onboarded"`. `onboarded` init = flag set **or** a `world-happyhour-zones` key already exists — so returning users are silently onboarded and never see it; only a genuinely new visitor does. |
| Trigger | In `handleAddClock`, on the first successful add: persist the flag immediately (survives a mid-animation refresh), then `setTaglineHiding(true)` (or, under reduced motion, `setOnboarded(true)` to cut instantly). |
| Unmount | `onTransitionEnd` fires on the `grid-template-rows` collapse (ignoring the earlier opacity fade) → `setOnboarded(true)`. |
| Tagline node | `338:3813`: `font-display font-black text-foreground text-[36px] leading-[38px] tracking-[-1px]`, `w-3/5` (60% of the `max-w-4xl` column), `px-[10px]` to align left with the button. Natural wrap, no forced `<br>`. |

## The reflow, without a JS animation lib

No framer-motion in the project. The tagline is wrapped in a CSS grid whose single row animates
`grid-rows-[1fr] → grid-rows-[0fr]`; the `overflow-hidden min-h-0` child collapses to zero height and
the add button + tile grid, being later siblings in normal flow, **slide up continuously** as the row
interpolates — the "elegantly animate up" for free, no FLIP/measuring. Two-phase feel via per-property
transition timing: `[transition-duration:180ms,360ms] [transition-delay:0ms,150ms]` over
`[opacity,grid-template-rows]` — opacity fades first (short), then the row collapses (longer, delayed).
`motion-reduce:transition-none` handles reduced motion.

## Location hint → Support instructions (same day)

The footer's dead "Allow location for a closer match." (shown on `geoDenied`) now helps the user fix it.
**Browser reality that shaped the design:** once location is *hard-blocked*, JS can't reopen the native
prompt (only browser site-settings can), and on iOS Safari the mount-time request often never prompts at
all. A click-to-reprompt would fail for exactly the blocked users who need it — so instead we route to a
Support section with per-browser instructions, which works in every state. No geolocation code touched.

| File | Change |
|---|---|
| `components/site-footer.tsx` | Hint copy → "Allow Happyhour to **access your location** for more precise local time and weather." with "access your location" a wouter `<Link href="/support">` (underline, hover→foreground). Still gated on `geoDenied`. |
| `pages/support.tsx` | New "Location access" section: intro + Safari / Chrome / Firefox blocks, each browser name linking to its canonical help page. Copy is verbatim from Khoi's `Scratch/2026-07-15-happyhour-location.md`. |

Copy went through three review rounds with Khoi, all on instruction *accuracy*: (1) don't send users to
System Settings when Safari has a per-site path; (2) the Chrome/Firefox steps were desktop-only and didn't
work on iPhone; (3) final copy supplied by Khoi. Key correctness point: **on iPhone, Chrome and Firefox
inherit the OS location permission** (Settings → Apps → Chrome/Firefox → Location), they don't expose a
per-site toggle in-app like desktop. Each entry now leads with the iPhone path. Safari link normalized off
a `…/en-sa/…` locale to the locale-neutral canonical. All three help URLs verified 200.

Verified: `tsc`/`build` clean; 24 Playwright assertions (footer copy + `/support` link + navigation; the
three canonical hrefs with `target=_blank rel=noopener noreferrer`; iPhone-path wording present; content
pages `/about`+`/privacy`+`/support` render **no** geo hint; link legible in light/dark/happy).
