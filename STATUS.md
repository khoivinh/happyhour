- **2026-08-01 (share message + picker) — four edits from the 2026-08-01 notes; 84 tests (up from 75), shipped + live.** (1) **Five-minute increments: attempted, then dropped the same day — don't retry with `step`.** `step={300}` shipped on all four `<input type="time">` and **failed device QA on iOS**, which still offered every minute. `step` on a time input is a **validity** constraint, not a picker one: iOS's wheel is a separate implementation (`WKContentViewInteraction`) that never receives it — the same architecture that makes `min`/`max` inert there ([WebKit #225639](https://bugs.webkit.org/show_bug.cgi?id=225639), still NEW Feb 2026) — and Chromium closed the exact request (`step="300"` still shows every minute) as **Won't Fix**, deliberately allowing invalid picks. **No browser snaps a time picker to `step`.** The only real options were rounding a typed value on commit, or hand-building the control (a `<select>` of 5-minute values is structurally sound — a select can't emit an unlisted value — but means owning 12/24-hour conversion `<input type="time">` does for free, plus a second editor across four render sites). Both judged worse than not having it, so the attribute was **removed rather than left in implying a guarantee it can't make**; a test now pins the *absence* of granularity. (2) **Return commits, Escape cancels** — *a deliberate departure from the note, which asked for both to commit*: Escape already means cancel twice here (share select-mode, Sharing View → resting) and everywhere on the platform. **Both keys `stopPropagation()`** — those bindings are on `document`, so an un-stopped Escape would close the editor *and* tear down share mode in one keystroke (`time-picker.spec.ts` covers exactly that). (3) **"Cancel" → "Done" on both bars** (sender's select bar + recipient's Sharing View bar): leaving select-mode undoes nothing, so "Cancel" promised a reversal that never happened. **testIds unchanged** (`button-share-cancel`, `button-share-import-cancel`) so specs and analytics stay put. (4) **Shares always order east-to-west** — previously the share inherited *grid* order, so the same three cities produced different links depending on tap order. The "Sort East to West" comparator was extracted to a module-level `byEastToWest()` and reused, so the two features can't drift; `?z=`, the recipient's tiles and the OG preview all inherit it. The local city **sorts into position** rather than staying pinned first. (5) **New `client/src/lib/share-text.ts` sends the times with the link** — live: `Current time in Tokyo 9:00 PM JST GMT+9/Paris 2:00 PM CEST GMT+2`; custom: `Tokyo 9:00 PM/Paris 2:00 PM`. - Key files: `client/src/pages/world-clock.tsx`, `components/digital-clock.tsx`, `components/time-zone-converter.tsx`, `components/logo-bar.tsx`, `components/shared-link-view.tsx`, `components/shared-link-auth-controller.tsx`, `components/commit-bar.tsx`, `components/share-selection-bar.tsx`, `components/registration-bar.tsx`, `App.tsx` (route scroll-to-top), `functions/_middleware.ts` + `functions/lib/preview.ts` (edge previews)
- Sharing View auth modes: a signed-out recipient gets **register mode** — `shared-link-auth-controller.tsx` (Clerk-only, mounted from `world-clock` when `isClerkConfigured`) computes `registerMode = !isSignedIn` and passes it to `SharedLinkView`, which then shows the blue `RegistrationBar` instead of the Commit Bar and renders **display-only tiles** (`DigitalClock showSelectCheck={false}`, no `onToggleSelect` — the tap layer and check hide but the geometry stays). On the ref-latched sign-in edge the controller branches on `user.createdAt`: new registrant → `onAdd(all keys)` (board + highlight), returning → no-op (Commit Bar reveals; `SharedLinkView` re-derives its pre-check). The no-Clerk test build renders the plain `SharedLinkView` (Commit Bar), so register mode is **live-QA only**.
- Registration Bar: `registration-bar.tsx` reuses `CommitBar`; the blue theme-independent skin is a `.registration-bar` wrapper in `index.css` overriding the seven `--share-bar-*` vars (they cascade into CommitBar's fixed child by DOM ancestry). Visibility is decided in `world-clock.tsx` from two in-memory flags (`addedThisSession`, `regDismissed`) — set by `handleAddShared` (added>0) and `TimeZoneConverter`'s `onClockAdded`; gated on `isClerkConfigured` so `useAuth` never runs without a provider (⇒ invisible in the Clerk-less test build). "Login or Sign Up" wraps Clerk's `SignInButton mode="modal"`, which *composes* the child onClick (child runs, then modal opens). Button says **"Later"** (not "Cancel"). The **same bar** is reused in the signed-out Sharing View (see the Sharing View auth-modes pointer).
- Tests: `npm test` (Playwright, `tests/`). Runs against a **prod build** — `analytics.ts` no-ops unless `import.meta.env.PROD`, so a dev server can't exercise analytics or the consent gate. Analytics assertions read `window.dataLayer`. Builds with `VITE_CLERK_PUBLISHABLE_KEY=` empty on purpose: a local `.env` key would compile in and mount `<ClerkProvider>`, so CI would test a different `App.tsx` branch than your machine.
- Sharing View states: `SharedLinkView` holds a local `mode: 'select' | 'resting'`. Select = checks + Commit Bar (arrival + post-Save); Resting = ⋯ menu ("Save {city}", or inert "Already saved" for owned cities), no bar. Arrival is Select — **except when the recipient already owns every shared city** (`newKeys.length === 0`), which starts in Resting (no empty bar). Cancel → Resting (view stays; `onDismiss` is analytics-only). **Esc** = Cancel (a `document` keydown guarded on `mode === 'select'`). Tiles pass `reserveGripSlot` so the content column doesn't shift Select↔Resting. Headline is type-aware (`headlineFor(count, !frozen)`); the Reset Time link's slot is reserved when `t != null`, hidden in Select Mode, and toggles frozen↔live (`toggleTime`) — label "Reset Time" ↔ "Restore Custom Time". The `?z=`/`?t=` params **persist** (no longer stripped on mount) so refresh re-enters. **Back/Forward (2026-07-19):** `handleAddShared` now `pushState`s the clean URL on top of the `?z=` entry (was `replaceState`), and a `popstate` listener re-runs `resolveShareFromLocation()` (the extracted mount parse, token-guarded against stale async), so Back returns to the share view and Forward to the board — a pure SPA transition. The logo escape is still a full `<a href="/">` reload (unaffected).
- Share previews (edge): the **first Pages Function on the HTML path** — `functions/_middleware.ts` rewrites per-share OG/Twitter meta via `HTMLRewriter` when `?z=` is present (else passes through); copy from the pure, unit-tested `functions/lib/preview.ts` `buildPreview(z, t)`, which replays the client key algorithm against `cities-top.json`. Image stays static `og.png`. `functions/` isn't in the app tsc `include`, so it never typechecks in `tsc --noEmit`; validate with `wrangler pages dev dist` + curl. **Deploy:** the Pages project's root dir must contain `functions/` or it silently no-ops.
- Share flow: link schema `/?z=<keys>[&t=<epoch ms>]` (`URLSearchParams` encodes commas as `%2C`; round-trips). **Sending:** select mode + link build in `time-zone-converter.tsx`; menu + tile selection in `digital-clock.tsx`. `DigitalClock` ellipsis menu renders when `!isSelectMode && (onShare || onSave)` — the board passes `onShare`/`onRemove`, the Resting view passes only `onSave`.
- Strokes: judge a tile stroke against **its own fill**, never the page. Use `cn()` for the tile's class chain: `border-transparent` and a state's `border-[…]` have equal specificity, so plain interpolation lets source order win and Tailwind emits `border-transparent` last. `tests/share-selection.spec.ts` guards it.
- City tiers: keys are **generated at runtime** by collision resolution, not stored — but identical in both tiers (verified 500/500), because `cities-top.json` is a population-ordered *prefix* of `cities.json`. Never resolve a user-supplied key against the top 500 alone (it's 500 of 30,481).
- The bottom of the viewport is shared: `SiteFooter`, the `CommitBar`, **and Silktide's cookie banner** (`#stcm-banner`, z-index 99999, always up for a first-time visitor — which every share recipient is). The bar steps up over it via `useConsentBannerHeight`. Anything new pinned to the bottom must account for all three.
- Timed UI in tests — **pick the right clock tool for the job** (2026-08-01 added the second half): `page.clock.install()` does **not** freeze time; use `install()` + `pauseAt(Date.now() + 60_000)` when you need to *control timers*. But when you only need `Date.now()` to hold still, use **`page.clock.setFixedTime(instant)`** instead — `pauseAt` can't reach a *fixed* target instant, because `install({time})` keeps ticking through page load and the target is already in the clock's past by the time you call it (`Cannot fast-forward to the past`). `share-text.spec.ts` needs `setFixedTime` to assert literal time strings; `time-picker.spec.ts` needs it because **the hero clock renders seconds while live**, so snapshot-comparing its text across an interaction races the wall clock (a self-inflicted flake, fixed same day — `Expected "6:49:34 PM" / Received "6:49:40 PM"`). **Never snapshot-compare `text-hero-time` across an interaction**; pin the clock, or assert on something stable — `button-reset-time` visibility is the real signal that a custom time was committed. Settled-position assertions must still poll (`toPass`/`expect.poll`); a single read lands mid-transition.
- Header geometry is one interlocked system: `TOGGLE_TOP` (world-clock.tsx) sets the drawer icon **and** the menu panel; `LogoBar`'s padding and `.hero-clock`'s padding-top share a baseline. Change one, re-measure all four. The system governs the panel's **top** edge only — as of 2026-07-25 the panel's height is `calc(100dvh - (topOffset - 18) * 2)`, so its bottom gap is *derived* from the same expression and stays symmetric (14px/14px at `TOGGLE_TOP = 32`) without further coordination. **Don't re-introduce a percentage of `dvh`** — `dvh` already excludes mobile browser chrome; the old `92dvh` was a leftover from the `100vh` era and is the bug this replaced.
- **The `node_modules.nosync` workaround is retired (2026-08-01).** The repo now lives on local disk at `~/Developer/Happyhour`, outside iCloud, so a plain `node_modules` is correct — verified 0 dataless files. Playwright's browsers live in `~/Library/Caches/ms-playwright`, outside iCloud, so they're never the problem.
- Share text: `client/src/lib/share-text.ts` builds the message that travels with a link — `buildShareText(keys, {use24Hour, customTime})` plus `buildSharePayload(text, url)` for the clipboard's single string.
