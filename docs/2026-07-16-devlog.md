# 2026-07-16 — Share-flow refinements (round 2)

Punch-list from Khoi's on-device review (`Obsidian/Scratch/2026-07-15-shotglass-sharing-refinements.md`)
after the 2026-07-15 share flow shipped. Files touched: `digital-clock.tsx`, `time-zone-converter.tsx`,
`share-selection-bar.tsx`, `world-clock.tsx`, `index.css`. Branch: `share-flow-refinements`.

## Why

The share flow worked but felt unfinished in use: entering select mode made tiles jump, a selected
tile's highlight could get stuck after cancelling, the commit bar was a low-contrast popover surface,
and city labels carried their region ("New York City, NY") in places it read as clutter.

## What changed

| Area | Change |
|---|---|
| **Hero label** | Region dropped — hero shows `heroCity.name` ("New York City"), not the province-qualified form. |
| **Tile padding** | Was top-heavy. Box padding → `pt-0.5 pb-3`; measured visual gap is now top ≈ 11px (= the 10px sides), bottom ≈ 13px (slightly greater, per spec). Reducing box top padding shifts grip + label together, so grip alignment is untouched. |
| **Context menu** | Widened 236 → **307px**; rows show region-free names via a new `cityShortName` prop; Happy stroke softened (`.happy .share-tile-menu` → light gold, vs the dark `--border` gold). |
| **Select mode — no shift** | Grip is hidden but its slot kept (`invisible` placeholder); the selection check now lives in the **ellipsis's exact flow slot** (was an absolute top-right badge), so entering select mode reserves both the left grip and right menu widths — nothing moves. |
| **Select mode — states** | Mid-tone `bg-muted` removed from unselected tiles (only selected tiles keep the gold highlight); unselected outline circle strengthened to `foreground/40`. |
| **Select mode — check** | Recolored to **monochrome foreground** (`bg-foreground text-background`): black check on light/Happy tiles, white on the dark tile — one consistent "selected" logic, replacing the orphaned blue that clashed with the gold highlight. |
| **Esc** | Escape exits select mode (keydown effect while `shareMode`). |
| **Add Time Zone** | No longer hidden in select mode (that caused a layout jump) — kept in place, `disabled` + dimmed. |
| **Drawer toggle** | Grayed + inert during select mode. `shareMode` is reported up via a new `onShareModeChange` prop (mirrors `onGeoDeniedChange`); the page holds `shareActive` and disables the toggle. |
| **Commit bar** | Re-themed per Khoi's spec via new `--share-bar-*` tokens: **black** (light), **yellow** (dark), **white** (Happy). `accent`/`accent-fg` drive the Share pill + checked box; checkbox border is full-contrast `--share-bar-fg` (was near-invisible); Cancel contrast raised. Stacks on mobile (checkbox left-aligned on top, actions below); body-padding clearance bumped to 132px on mobile for the taller bar. |

## The stuck-highlight bug

Choosing **Share** flips `shareMode` on, which unmounts the tile's menu `Popover` — Radix never fires
`onOpenChange(false)`, so the tile's local `isDropdownOpen` stayed `true` and repainted the dropdown-open
cream tint the moment select mode exited. Fix: the Share row now resets `setIsDropdownOpen(false)`
alongside `setIsMenuOpen(false)` before calling `onShare`.

## Design gate

Ran the 2-critic loop (Happyhour-fidelity + Apple-HIG) on the changed surfaces. Round 1 (both `revise`)
surfaced: orphaned-blue selection check, invisible bar checkbox (worst on the yellow bar), faint
unselected outlines, low Cancel contrast, residual top-heavy tile padding. Fixed → **both `pass`** on the
real build. Where a critic note contradicted Khoi's explicit written spec (black light-bar; bottom
slightly greater than top), Khoi's spec was kept — the loop is for the unspecified details.

## Verification
