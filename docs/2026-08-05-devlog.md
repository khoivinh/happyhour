## 1. The tile meta line no longer moves

The note attributed the shift to the **Time Zone Names** toggle. It isn't that: `showZoneAbbr` only
swaps the label's text (`GMT+2` → `CEST`) via `zoneLabel()`, so it cannot change row height. The
culprit is the **Relative Time** badge — which is what the two attached screenshots actually
compared, and what the note's own fix sentence named.

Measured in the browser rather than reasoned about:

| State | Row height | Label y |
|---|---|---|
| No badge | 16px | 476 |
| Badge mounted | 18px | 477 |

The badge is `leading-[16px]` plus a 1px border top and bottom = 18px; the bare label inherits
`text-xs`'s 16px line-height. With `items-center` on the row, mounting the badge grows the row 2px
and re-centres the label a pixel lower — every tile on the board twitches at once.

Fix is a floor equal to the badge's height, on both the desktop and mobile rows
(`digital-clock.tsx`). This is the file's existing idiom: the hero's meta row is pinned to a fixed
`h-[28px]` for the same reason.

## 2. Hero Clock: ellipsis menu and select check

The hero had no menu — `time-zone-converter.tsx` passed neither `onShare` nor `onSave`. It now gets
a trailing control that is a ⋯ at rest and a select check while a share is being assembled, wrapped
with the time in a `flex items-end justify-between` row so it bottom-aligns to the numbers' baseline
as they scale with `--hero-ratio`.

Everything is reused from the tiles: `EllipsisCircleIcon`, the trigger's class string, the Popover
with `align="end"`, and the check's 17×17 span with its `Check` at `h-[11px] strokeWidth={3}`. Both
controls sit in the same `py-[11px] px-[5px]` box, so the swap cannot reflow the row — that padding
match is why the tiles' own ellipsis↔check swap is stable, and the comment there says so.

Two deliberate divergences from the tiles:

- **The check is its own tap target**, not `pointer-events-none`. A tile delegates the tap to a
  full-tile overlay; the hero has none, and its body is the time `<p>`.
- **`isLocked` / `isBlocked` are dropped.** They mean "already saved" and "board is full" — both
  Sharing-View concepts. The hero is only ever in or out.

State reuses `includeLocal`, which already fed `shareKeys`; no new state. The menu item enters share
mode with it true, and the check toggles it from there.

## 3. Reverted: making the hero numbers inert during share mode

The plan called for guarding `handleTimeClick` while share mode is active, on the reasoning that
grid tiles go inert in select mode. Implementing it broke `time-picker.spec.ts:64`, which guards a
2026-08-01 decision recorded in `STATUS.md`: the hero editor **works** during share mode, and Escape
closes the editor without tearing down the share bar (both keys `stopPropagation()` precisely so).

The guard was never needed — the check is its own button, so the numbers and the check never
compete. Removed, with a comment naming the spec so it isn't re-added. The tile-goes-inert rule is
about a tile *becoming* the selection target; the hero doesn't.

## 4. Commit Bar checkbox now governs the link

"Include my local time" → **"Include Happyhour link"**, default ON. The local-time job moved to the
hero (§2), so the checkbox took over the URL, which was previously always attached.

`data-testid="checkbox-include-local"` is unchanged, the same call made for "Cancel" → "Done" on
2026-08-01 — specs and analytics stay put across a label change.

With the link off, the share sheet receives **no `url` key at all** rather than `url: null`, which
isn't valid `ShareData`; the clipboard gets the text alone with no trailing blank line.

## 5. Share text: time first, city last

```
LIVE   (TZ Names On)   Current time — 9:00 PM JST Tokyo/2:00 PM CEST Paris/8:00 AM EDT New York City
LIVE   (TZ Names Off)  Current time — 9:00 PM Tokyo/2:00 PM Paris/8:00 AM New York City
CUSTOM (either)        9:00 PM Tokyo/2:00 PM Paris/8:00 AM New York City
```

Four changes from the old form:

1. **City moves last.** The numbers now line up down the left edge when several are scanned at once.
2. **GMT offset dropped** — `JST GMT+9` becomes `JST`. `zoneSuffix` deleted.
3. **Zone gated on the Time Zone Names preference**, via a new `showZoneAbbr` option. It reuses the
   tiles' own `zoneLabel()` rather than calling `getZoneAbbreviation` directly, so the share text and
   the screen can no longer drift on how a zone is named — and the `GMT+X` fallback comes free.
4. **`Current time in ` → `Current time — `.** The old prefix parsed as a sentence only while the
   city came first; with the time leading it is a label, not a clause.

Custom shares still omit zones **even when the setting is on** — a fixed instant implies them, and
that live/custom distinction was a deliberate 2026-08-01 call. The setting governs live shares.

## 6. Tests: 84 → 92

New coverage: zones dropped when Time Zone Names is off; the link checkbox's default and both of its
effects (clipboard, share sheet); the hero menu opening a share with one city; the ⋯→check swap not
moving the numbers; the check round-tripping the city; and the meta-row height guard.

**The meta-row guard was silently useless on first write, and that is the lesson worth recording.**
It passed with the fix removed, for two independent reasons:

- **The seeded city already had a badge.** Paris carries `NEXT DAY` at most real instants relative to
  a US-local hero, so toggling Relative Time only changed the badge's *contents* — the row was
  already 18px. The test now picks a tile with no day badge dynamically, from a seed spanning six
  timezones so one always qualifies whatever the runner's zone, and asserts that precondition.
- **`getByText` matched the `<p>` ancestor, not the label span.** The row's own `y` never
  moves — its *height* changes. Measuring the ancestor was measuring the one thing the bug doesn't
  affect. The row now carries `data-testid="tile-meta-{key}"` and the assertion is on height.

Both were found by writing a throwaway probe spec that dumped real geometry, after the mutation test
passed twice against a bug that was definitely present. **A regression guard that has not been
mutation-checked is a guess** — this one looked correct twice while testing nothing.
