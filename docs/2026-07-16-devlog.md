# 2026-07-16 — Share-flow refinements (round 2)

Punch-list from Khoi's on-device review (`Obsidian/Scratch/2026-07-15-shotglass-sharing-refinements.md`)
after the 2026-07-15 share flow shipped. Files touched: `digital-clock.tsx`, `time-zone-converter.tsx`,
`share-selection-bar.tsx`, `world-clock.tsx`, `index.css`. Branch: `share-flow-refinements`.

## Why

The share flow worked but felt unfinished in use: entering select mode made tiles jump, a selected
tile's highlight could get stuck after cancelling, the commit bar was a low-contrast popover surface,
and city labels carried their region ("New York City, NY") in places it read as clutter.

## What changed

| Area | Change |
|---|---|
| **Hero label** | Region dropped — hero shows `heroCity.name` ("New York City"), not the province-qualified form. |
| **Tile padding** | Was top-heavy. Box padding → `pt-0.5 pb-3`; measured visual gap is now top ≈ 11px (= the 10px sides), bottom ≈ 13px (slightly greater, per spec). Reducing box top padding shifts grip + label together, so grip alignment is untouched. |
| **Context menu** | Widened 236 → **307px**; rows show region-free names via a new `cityShortName` prop; Happy stroke softened (`.happy .share-tile-menu` → light gold, vs the dark `--border` gold). |
| **Select mode — no shift** | Grip is hidden but its slot kept (`invisible` placeholder); the selection check now lives in the **ellipsis's exact flow slot** (was an absolute top-right badge), so entering select mode reserves both the left grip and right menu widths — nothing moves. |
| **Select mode — states** | Mid-tone `bg-muted` removed from unselected tiles (only selected tiles keep the gold highlight); unselected outline circle strengthened to `foreground/40`. |
| **Select mode — check** | Recolored to **monochrome foreground** (`bg-foreground text-background`): black check on light/Happy tiles, white on the dark tile — one consistent "selected" logic, replacing the orphaned blue that clashed with the gold highlight. |
| **Esc** | Escape exits select mode (keydown effect while `shareMode`). |
| **Add Time Zone** | No longer hidden in select mode (that caused a layout jump) — kept in place, `disabled` + dimmed. |

| **Commit bar** | Re-themed per Khoi's spec via new `--share-bar-*` tokens: **black** (light), **yellow** (dark), **white** (Happy). `accent`/`accent-fg` drive the Share pill + checked box; checkbox border is full-contrast `--share-bar-fg` (was near-invisible); Cancel contrast raised. ## The stuck-highlight bug

Choosing **Share** flips `shareMode` on, which unmounts the tile's menu `Popover` — Radix never fires
`onOpenChange(false)`, so the tile's local `isDropdownOpen` stayed `true` and repainted the dropdown-open
cream tint the moment select mode exited. Fix: the Share row now resets `setIsDropdownOpen(false)`
alongside `setIsMenuOpen(false)` before calling `onShare`.

## Design gate

Ran the 2-critic loop (Happyhour-fidelity + Apple-HIG) on the changed surfaces. Round 1 (both `revise`)
surfaced: orphaned-blue selection check, invisible bar checkbox (worst on the yellow bar), faint
unselected outlines, low Cancel contrast, residual top-heavy tile padding. Fixed → **both `pass`** on the
real build. Where a critic note contradicted Khoi's explicit written spec (black light-bar; bottom
slightly greater than top), Khoi's spec was kept — the loop is for the unspecified details.

## Verification

`tsc` + `build` clean. `scratchpad/verify-share.mjs` extended to **35 assertions, all pass** — new coverage:
no-shift-on-enter (city-label left x and check-in-ellipsis right x unchanged), stuck-highlight neutral
after cancel, Esc exits, Add-Time-Zone disabled-not-hidden, drawer toggle disabled + `pointer-events:none`,
menu width 307px and region-free name. Screenshots re-passed both critics across light/dark/Happy,
desktop + mobile.

## Second session — `node_modules` excluded from iCloud sync

Not feature work. Fallout from a Mac performance check (`Research/Tech Support`) that found every
Node project under `Claude Projects/` syncing its `node_modules` to iCloud Drive.

### Why

`.gitignore` only talks to git. iCloud has never heard of it — it saw `node_modules` sitting in its
sync tree and was replicating all **14,342 files (240 MB)** to Apple's servers and every other
device. Compounding it, iCloud's **Optimize Mac Storage is enabled**, so it's free to decide a cold
file deep in `node_modules` is evictable and swap it for a `.icloud` stub. That surfaces as a build
failing on a missing module that's visibly right there in Finder. Nothing had been evicted yet
(0 stubs found), so this was latent rather than actively breaking anything.

### What changed

| Change | Detail |
|---|---|
| `node_modules` | Renamed → `node_modules.nosync`, with `node_modules` now a symlink to it. iCloud skips any path ending in `.nosync`. |
| `.gitignore` | Added `node_modules.nosync/`. The existing `node_modules` line doesn't match the renamed dir, so git had started seeing the whole tree as untracked — a stray `git add -A` could have committed 14k files. |

`npm install` follows the symlink and writes into the real directory, so this survives reinstalls.

### Verification

`require.resolve('vite/package.json')` resolves through the symlink to the `node_modules.nosync/`
realpath (node resolves symlinks to realpath by default — expected, and harmless here).
`npx tsc --noEmit` clean. `npm run build` ✓ 2.86s, output unchanged.

### Caveat

`.nosync` is well-established folklore, **not a documented Apple API**. If a macOS update changed
the behavior, syncing would silently resume with no error. The durable fix is moving `Code/` out of
iCloud entirely — source is already on GitHub, so iCloud is redundant backup for versioned code.
That's a separate migration (paths in `CLAUDE.md`, Cursor workspaces) and wasn't attempted here.

Remote-control session; Khoi out for the afternoon. Picked off the backlog items that don't need a

### The discovery that reframed the task

"Add Playwright coverage for the cookie flow" assumed a suite to extend. **There isn't one, and
never has been.** No spec file appears anywhere in git history, `@playwright/test` wasn't a

So the work became: establish the suite (Khoi chose committing `@playwright/test` properly over

### How the tests assert analytics

`analytics.ts` gates every event on `import.meta.env.PROD`, so a dev server can't exercise the
analytics path at all — and the cookie banner's entire job is gating analytics. So the suite runs
against a **production build** via `vite preview`. No stubbing is needed: `index.html` declares its
own `function gtag(){dataLayer.push(arguments)}` inline, so events land in `window.dataLayer`
whether or not Google's script loads (it's blocked, along with fonts, weather, and the Figma
capture script, to keep runs hermetic).

### Two traps worth recording

**The build bakes in `.env`.** A local `VITE_CLERK_PUBLISHABLE_KEY` gets compiled into the bundle,
which mounts `<ClerkProvider>` and pulls Clerk over the network at boot. Tests would depend on a
developer's `.env` and on Clerk being reachable — and CI, with no `.env`, would silently exercise a
*different branch of `App.tsx`*. The config now builds with the key explicitly empty, forcing the
localStorage-only path the app already supports, identically everywhere.

**A stale `vite preview` invalidates everything.** With `reuseExistingServer: true`, a preview
server left running from earlier serves an old `dist/` — a mutation test run this way "passed"
against code that no longer existed. Set to `false`; the suite always builds what it tests.

### The flaky test, and why it wasn't the bug it looked like

The cap-toast test failed ~1-in-8, worse under parallelism. It looked like a lost toast — the
analytics were provably correct on every run (`{count:3, added:1, dropped:2}`, 37/37), so `toast()`
was firing but nothing rendered. It wasn't a race in shadcn's toast store: the toast has Radix's
default **5-second life**, and under CPU contention the gap between clicking Add and asserting can
exceed it. The toast was correct and already gone. `page.clock.install()` took it to 8/8, then
102/102.

> **Correction (fourth session):** the diagnosis was right, the fix's *reasoning* was wrong.
> `page.clock.install()` does **not** freeze time — measured, it ticks along with the wall clock,
> and a 2s timer still fires after 3s of real time. Only `install()` **+ `pauseAt()`** actually
> stops timers. Those runs passed because they were fast, not because time was frozen; the same
> mistake reappeared as a 1-in-3 flake on the arrival highlight and was caught there. Moot for the
> toast itself (it's gone — see below), but any test relying on `install()` alone is unfrozen.

### Verification

`tsc` + `build` clean. 34/34 pass; 102/102 under `--repeat-each=3` parallel. **Mutation-tested**
with a forced rebuild: reverting the cap fix, the analytics params, and the dismiss event fails 7
of the 10 share-import tests, and restoring passes all 10 — the tests catch what they claim to.

### Found, not fixed (out of scope)

- **The footer isn't a landmark.** `SiteFooter` renders inside `<main>`, and a `<footer>` scoped to
  `main` isn't exposed as `contentinfo` — so screen readers lose footer landmark navigation on
  every page. Confirmed by probe, and it's why the tests locate `#root footer` instead. One-line
  structural fix (move it outside `<main>`), but it's a change to shipped markup.
- **The cookie modal's save button lies.** It reads "Accept all" even when you've just switched
  Analytics *off* (`preferences.saveButtonText` in `index.html`). It does honour the toggle —
  verified — but the label contradicts the action. Worth folding into the queued modal redesign.
- **Silktide injects a second `<h1>`** ("Customize your cookie preferences") into every page.
- **A Figma capture script ships to production.** `index.html` loads
  `https://mcp.figma.com/mcp/html-to-design/capture.js` on every page load — a third-party script
  on a site that otherwise takes consent seriously. Likely a dev artifact.

## Fourth session — the Sharing View, and two strokes that were never there

Punch-list from `Obsidian/Scratch/2026-07-16-shotglass-sharing.md` (filed under `#shotglass`, but
Happyhour work — same as the 2026-07-15 note). Branch: `sharing-view`, off `main` at `1bc4796`.
Four asks: 3px of tile margin, quiet the Happy select-mode decoration, a Copy Link button, and
replace the incoming-share dialog with a dedicated Sharing View (Figma `344:3787`).

### The "two strokes" were one bug and one bad value — and neither was the doubled stroke

Khoi's screenshot showed a selected Happy tile ringed by two concentric strokes: a pale band
outside a gold one. The source looked like an obvious culprit — `digital-clock.tsx` applied a 1px
`border` **and** a 1px inset ring in the same colour. But gold-on-gold can't produce a *pale* outer
band, and a pixel scan of the screenshot confirmed the order: canvas → pale → gold → fill.

A DOM probe found the real mechanism, and it's worse than a doubled stroke:

```
borderTopColor: "rgba(0, 0, 0, 0)"                        ← the gold border never painted
boxShadow:      "rgb(234, 183, 0) 0px 0px 0px 1px inset"  ← the ring was standing in for it
backgroundColor: "rgb(255, 240, 168)"                     ← pale, clipped to border-box
```

`border-transparent` on the base was **beating** the state's `border-[var(--tile-sel-border)]`.
Equal specificity, so CSS source order decides — and Tailwind emits `border-transparent` last
(offset 16999 vs 16368 in the built stylesheet). The tile's background then showed *through* that
1px transparent border, and the inset ring painted gold just inside it. Pale band, then gold band.

The scope is bigger than select mode: `isDropdownOpen` and `isBeingDragged` use the same pattern,
so **the tile has never had a visible border in any state**. Select mode only appeared to, via a
ring that reads as a workaround someone added when the border didn't show, without knowing why.
The comment promising "active states switch the border color only" has never been true.

Fixed by swapping the template literal for `cn()` — `tailwind-merge` resolves the conflict
deterministically instead of leaving it to the stylesheet's ordering. Verified: the border now
paints and the live edge at 4× DPR is exactly one stroke, `canvas → 4 device px of #eab700 → fill`,
no bleed. The inset ring is gone as redundant.

**The same bug, again, on the commit bar.** `border-[var(--share-bar-fg)]/10` generates no rule at
all (Tailwind can't alpha-composite an arbitrary `var()`), so the bar fell through to the global
`* { @apply border-border }` and wore `--border`. Invisible against the light and dark bars — but a
hard olive `#a3922a` ring around Happy's white one. That *was* the bar's "too pronounced"
decoration. Fixed with explicit `--share-bar-border` / `--share-bar-subtle` tokens per theme.

### The Happy token, decided by measurement rather than taste

With the stroke finally painting, `#eab700` was still the outlier Khoi flagged. Measuring each
theme's stroke against **its own fill** in CIELAB made the case precise:

| theme | canvas | fill | stroke | ΔE(fill, canvas) | ΔE(stroke, fill) |
|---|---|---|---|---|---|
| light | `#ffffff` | `#fdf7ca` | `#ffedbd` | 23.2 | **5.7** |
| dark | `#171717` | `#3d3520` | `#5c4f2a` | 20.7 | **14.8** |
| happy (old) | `#ffd900` | `#fff0a8` | `#eab700` | 51.4 | **47.2** |
| happy (new) | `#ffd900` | `#fff0a8` | `#ffe799` | 51.4 | **5.7** |

Happy's fill already clears its canvas by more than double light's or dark's, so it needs the
*quietest* stroke of the three — and had the loudest by 8×. New value `#ffe799` = hsl(46,100%,80%),
solved to sit at light's 5.7. The rule is now written into `index.css`: judge a stroke against the
fill, never against the page. Reading it as "separate the tile from the page" is exactly what
produced `#eab700`.

**Dark came down too**, `#5c4f2a` → `#473d21` (14.8 → 5.7). Initially left alone as unasked-for,
but the spec says "in each of the three modes, the stroke should only be dark enough … and no
darker" and "coordinate changes … so that all three are consistent" — that's a general rule, not a
Happy-only carve-out, and both critics independently called dark the remaining outlier. Rendered
side by side before changing it. Easy to revert if Khoi disagrees; it's one token.

### The Sharing View

New `components/shared-link-view.tsx`, rendered from `world-clock.tsx` in place of the hero + board
while `?z=` is live. The dialog is gone entirely.

| Piece | Note |
|---|---|
| Headline | "Two time zones shared with you." Numbers spelled out, singular at one. Reuses the onboarding tagline's type (Figma's spec for both is identical) but not its `sm:w-3/5`, which is tuned to wrap a longer sentence. |
| Tiles | `DigitalClock` in select mode with a new `pinHoverSkin`: every tile wears the hover fill at rest, because all of them are being offered — the fill can't distinguish anything, so the check carries selection. |
| Locked check | New `isLocked`. A city already on the board gets a muted *filled* check — locked is a settled fact, and an empty circle would say "not chosen", the opposite of the truth. |
| Cap | `room = 16 − owned`; pre-check what fits, refuse the rest until something is unchecked. The cap is now enforced where the recipient can still act on it. |
| Bar | Shares a new `CommitBar` shell with the sending end, so the two can't drift. Mounting it reserves the footer clearance — the Sharing View forgetting to was exactly how the bar first landed on top of the footer. |

### Superseded: the cap toast is gone

Pre-check-and-block means nothing can be selected that wouldn't survive the merge, so `dropped` is
always 0 and the toast written this morning could never fire. Removed rather than left as
untestable dead code — the bug it addressed (cities vanishing silently) is better fixed by
prevention than by an apology afterwards. The `.slice(0, MAX_CLOCKS)` clamp stays as a guard.
`share_link_added` is now `{ count, added, capped }`: `count` is what the link offered (so the
`share_link_opened` funnel still compares), `added` is what landed, `capped` records whether the
limit is *why* the rest didn't.

### The highlight had to grow up

Two things blocked "flash the added cities", neither visible from outside:
- `highlightedZone` was a single `string | null`. Widened via a `highlightedZones` prop.
- `animate-highlight-yellow` hardcoded `#fdf7ca` and a matching glow, so it flashed light cream on
  dark's near-black tiles and on Happy's yellow page. Now keyed off `--tile-sel-bg`. **This also
  fixes the ordinary add-a-city highlight**, which has had the same bug in dark mode all along.

### Verification

`tsc` + `build` clean. **52 tests**, and **520 test-runs green** across three stress rounds
(`--repeat-each=3 --workers=8` twice, then `--repeat-each=4 --workers=10`) — deliberately at higher
parallelism than the default, since both flakes below only appeared under contention. The 10 dialog
tests were rewritten against the new surface; `tests/share-selection.spec.ts` is new (Copy Link, the
two bar shapes, and the stroke guards).

Mutation-tested, each mutation failing exactly the test that guards it and nothing else: removing
the cap block fails "refuses to check more than fits"; `isLocked → false` fails "a city already on
the board is locked"; reverting `cn()` to a template literal and the bar border to the alpha
modifier fails both stroke guards.

Those stroke guards are new and worth keeping: the bug class is "the class you wrote never
applied", which no type check catches and no visual review reliably catches — on two of three
themes the wrong value happened to be invisible. They assert the mechanism (border resolves to its
token; `border-transparent` is gone from the class list), not a hex the design may still tune.

Three traps the tests themselves surfaced:

- **`page.clock.install()` does not freeze time.** It ticks with the wall clock — measured directly:
  a 2s timer fires after 3s of real time and the page's `Date.now()` advances 3004ms. Only
  `install()` **+ `pauseAt()`** stops it (`Date.now()` then advances 0ms). This produced a 1-in-3
  flake on the arrival highlight (whose 2s retire timer was quietly running), and it means the third
  session's toast fix was passing on speed rather than on frozen time. It was also lurking in the
  new Copy Link test, which asserts a 5s "Link copied" toast — frozen now, before it could bite.
  And `pauseAt(Date.now())` is itself a race: the fake clock ticks between the two calls, so under
  load the target is already its past and pauseAt throws "Cannot fast-forward to the past". Aim
  ahead (`+60s`) — nothing is scheduled before `goto`, so the jump fires nothing.
- **`page.addInitScript` re-runs on every navigation *and reload*.** `seedZones` was re-asserting
  the starting board and undoing what the app had saved, so a reload test would have been testing
  the seed, not the product. It now only writes when the key is absent.
- **`toHaveCSS`, not a one-shot read**, for anything mid-transition: Chrome reports the interpolated
  colour, which serialises as `rgba(…, 1)` rather than `rgb(…)` and fails on a technicality.

### The design gate, and a bug it led to indirectly

Ran the 2-critic loop (Apple-HIG + Happyhour-fidelity) on the Sharing View, the retuned strokes and
the bar, across three themes plus mobile. Both returned **revise**.

**Both were wrong on their top item.** Each claimed the commit bar occludes the footer, and one
added that the copyright line "never renders". Both judged from scroll-0 screenshots. Measured: at
max scroll `footerBottom 796` vs `barTop 814` — an 18px gap — and the full footer, copyright
included, renders fine. `CommitBar` reserves the clearance on mount. The Sharing View just *is*
short (no hero, two tiles), so the footer sits mid-page while the bar floats at the viewport
bottom — which is exactly what the Figma frame shows too.

But taking that screenshot surfaced something neither critic could see: **the "allow location"
notice was showing on the Sharing View**. `geoDenied` starts false and is only ever set by
`TimeZoneConverter` — which the Sharing View doesn't render — so its being true was proof the board
had mounted first. It had: the `?z=` keys resolve async (they need the city lookup), so the
recipient's own clocks mounted, requested geolocation, and painted for a frame before the Sharing
View replaced them, leaving the denied-prompt notice stranded on a surface with no local time on
it. Fixed by holding the board back on a `sharePending` flag read synchronously from the URL —
whether `?z=` exists is knowable immediately even though its keys aren't. Now covered by a test;
note the observer must attach in the very first script, since module scripts run *before*
`DOMContentLoaded` and an observer added there misses the flash entirely.

**Acted on** (where the critics agreed with each other and with the spec):
- Dark's stroke → `#473d21` (above).
- Dark's `--share-bar-subtle` → `rgba(0,0,0,0.16)`: 8% black over a saturated yellow bar read as a
  smudge rather than a chip, where the same value lands cleanly on white or near-black.
- **Blocked tiles now say so.** At the cap, unchecked cities looked identical to checkable ones and
  silently ignored taps. New `isBlocked` on `DigitalClock` — distinct from `isLocked`, because
  unchecking another city frees it, so it isn't disabled, just out of room: faded ring,
  `cursor-not-allowed`, `aria-disabled`. Playwright now refuses to click it without `force: true`,
  which is a decent proxy for assistive tech seeing it the same way.

**Not acted on** (spec conflicts — flagged for Khoi, not overruled):
- HIG argues the **locked gray check reads as disabled** and wants a text caption instead. The spec
  says "show a check mark but in gray".
- HIG argues **Copy Link is redundant** where a share sheet exists and should be dropped. Khoi
  chose "Copy Link always; Share only if there's a sheet".
- HIG argues the **empty gap** above the footer reads as an unfinished page. The Figma has it; the
  fidelity critic (which saw the frame) didn't raise it.
- **Noun drift**: "time zones" (headline, per Figma) vs "cities" (bar, per spec) for one object on
  one screen. Both strings are Khoi's, verbatim.
- Fidelity flags that with interactive checks, **selection now rests on a 24px glyph alone** —
  checked and blocked tiles have identical fills. Its read: "Hover State at all times" may have
  meant the *base* state, leaving room for a tint on top. Worth a decision.
- HIG called light's blue Share pill "the only blue in the product". It isn't — blue is light's
  `--share-bar-accent` and `--ring`. Disregarded.
